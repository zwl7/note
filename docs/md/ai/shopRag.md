## 二、系统架构与全局设计约束（杜绝代码结构混乱、分层违规）

这部分锁定代码的整体骨架，明确分层规则、模块边界、核心设计原则，避免 Codex 生成的代码出现职责越界、结构混乱的问题。

1. 架构分层与职责边界（必须明确，无任何模糊空间）

   - 明确架构模式：如 MVC、DDD 分层、微服务拆分、前后端分离架构

   - 每层的强制职责与禁止规则：

     

     示例（后端 MVC）：

     ```
     controller层仅负责参数校验、请求响应封装、鉴权校验，禁止编写任何业务逻辑；service层仅负责业务逻辑编排与核心规则实现，禁止直接操作数据库；dao层仅负责数据读写，禁止编写业务逻辑；model层仅负责数据模型定义，禁止包含业务代码
     ```

   - 目录结构强制约定：明确每个目录的用途，代码必须存放的对应路径，示例：

     plaintext

     ```
     /cmd：项目启动入口
     /internal/controller：接口层代码，按模块分子目录
     /internal/service：业务逻辑层，按模块分子目录
     /internal/dao：数据访问层
     /internal/model：数据模型/结构体定义
     /internal/utils：通用工具函数，禁止业务逻辑
     /configs：配置文件
     /test：单元测试代码
     ```

2. 核心模块划分与依赖规则

   - 全量模块清单：如用户模块、订单模块、商品模块、支付模块，每个模块的核心职责
   - 模块间依赖关系：明确允许的依赖方向（如订单模块依赖用户 / 商品模块，禁止反向依赖）、模块间通信方式（HTTP/gRPC/ 消息队列）
   - 跨模块调用的强制规范：如必须通过接口层调用，禁止直接依赖内部实现

   

3. 全局核心设计原则（硬约束）

   - 错误处理体系：全局统一异常处理机制、错误码规范（如 4xxxx 客户端错误、5xxxx 服务端错误，每个模块分配固定错误码段）、异常必须全量处理（禁止忽略 error / 异常）
   - 事务管理规范：明确事务开启场景、传播机制、隔离级别、回滚规则（如多表写操作必须开启事务，异常全量回滚）
   - 安全全局规则：鉴权方式（JWT/SESSION）、免鉴权接口清单、权限校验规则（如管理员接口必须校验用户角色）、SQL 注入防护（禁止拼接 SQL，必须参数化查询）、XSS 防护规则、敏感数据加密规则（如密码必须 bcrypt 加密，成本因子 10）
   - 幂等性设计规范：明确必须做幂等的接口场景、幂等实现方式（如唯一请求号、唯一索引）
   - 代码复用规则：通用逻辑必须封装到公共工具包，禁止重复代码，明确已有的可复用封装（如全局响应函数、鉴权中间件）

### 每个功能点（用例）的详细规格（必填项）

表格

| 要点                   | 编写要求与示例                                               |
| ---------------------- | ------------------------------------------------------------ |

| 功能基础描述           | 一句话明确功能用途、触发场景、操作角色、业务目标，无多余表述 |

| 出参完整规范           | 明确成功 / 失败的统一响应结构，每个字段的名称、类型、含义，禁止返回敏感字段示例：统一响应结构`{code: int, msg: string, data: {user_id: int, token: string, phone: string}}`，禁止返回 password 字段 |

## 四、代码生成强制规则（给 Codex 的直接生成指令，规避不合规代码）

这部分是对代码本身的硬性要求，确保生成的代码符合编码规范、可运行、可维护，避免出现风格混乱、语法错误、安全漏洞。

1. 编码风格与命名规范

   - 明确遵循的官方规范：如 Go 的 gofmt、Python 的 PEP8、Java 的阿里巴巴开发规范
   - 命名强制规则：如变量 / 函数小驼峰、常量全大写、表名 / 数据库字段下划线命名、结构体大驼峰，所有定义必须加中文注释
   - 注释规范：每个函数必须加注释，说明功能、入参、出参、异常场景；每个结构体、表字段、接口必须加注释；核心业务逻辑必须加行内注释

   

2. 代码质量强制要求

   - 必须生成完整可编译 / 可运行的代码，无语法错误、无未声明的变量 / 依赖、无占位符
   - 所有依赖必须在对应的包管理文件（go.mod/pom.xml/package.json）中完整声明
   - 禁止硬编码魔法值、敏感配置、密钥，所有常量必须统一定义
   - 必须处理所有异常 / 错误，禁止静默忽略（如 Go 中禁止用`_`忽略 error，除非文档明确允许）

   

3. 测试代码生成规则

   - 明确测试框架：如 Go testing、Java JUnit5、Python pytest
   - 测试用例覆盖要求：必须覆盖正常场景、异常场景、边界场景，核心业务逻辑测试覆盖率≥80%
   - 测试代码存放路径、命名规范

   

4. 安全合规强制禁令

   - 禁止硬编码 AK/SK、数据库密码、JWT 密钥等敏感信息
   - 禁止 SQL 拼接，必须使用参数化查询 / ORM 预编译
   - 禁止在响应、日志中输出完整的敏感信息（密码、身份证号、银行卡号）
   - 所有用户输入必须执行校验与过滤，禁止未校验直接使用
