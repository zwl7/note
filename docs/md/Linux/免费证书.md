### **1. 安装 Certbot**

```
# Ubuntu/Debian
sudo apt update && sudo apt install certbot python3-certbot-nginx -y

# CentOS/RHEL
sudo yum install epel-release -y && sudo yum install certbot python3-certbot-nginx -y
```

> 💡 `python3-certbot-nginx` 是 Nginx 插件，支持自动修改配置。若使用 Docker/容器化部署，建议**不装此插件**，改用 `webroot` 或 `standalone` 模式。

------

### **2. 四种常用申请模式**

表格

| 模式           | 命令示例                                                     | 适用场景          | 特点                                           |
| :------------- | :----------------------------------------------------------- | :---------------- | :--------------------------------------------- |
| **Nginx 插件** | `certbot --nginx -d example.com`                             | 传统主机部署      | 自动获取证书 + 修改 Nginx 配置 + 重定向 HTTPS  |
| **Webroot**    | `certbot certonly --webroot -w /var/www/html -d example.com` | Docker/自定义路径 | 不中断服务，需指定网站根目录                   |
| **Standalone** | `certbot certonly --standalone -d example.com`               | 无 Web 服务器时   | 自带临时 HTTP 服务器，**需先停掉 80 端口占用** |
| **DNS 验证**   | `certbot certonly --dns-cloudflare -d *.example.com`         | 通配符证书        | 通过 DNS API 验证，无需开放 80/443 端口        |

#### **多域名申请**

```
# 一张证书包含多个域名（SAN 证书）
certbot certonly --webroot -w /var/www/html \
  -d example.com -d www.example.com -d api.example.com
```

#### **交互式申请**

不带 `-d` 参数直接运行 `certbot`，会进入交互向导逐步填写。

### **3. 证书文件位置与结构**

申请成功后，证书存放在 `/etc/letsencrypt/live/<域名>/`：

表格

| 文件            | 用途                                | Nginx 配置项              |
| :-------------- | :---------------------------------- | :------------------------ |
| `fullchain.pem` | 完整证书链（服务器证书 + 中间证书） | `ssl_certificate`         |
| `privkey.pem`   | 私钥                                | `ssl_certificate_key`     |
| `chain.pem`     | 仅中间证书（OCSP Stapling 用）      | `ssl_trusted_certificate` |
| `cert.pem`      | 仅服务器证书（一般不单独使用）      | —                         |

> ⚠️ **始终使用 `fullchain.pem`** 而非 `cert.pem`，否则部分客户端会因缺少中间证书而报错。

### **4. 自动续期管理**

Let's Encrypt 证书有效期 **90 天**，Certbot 安装时自动创建 systemd timer 或 cron 任务。

bash

编辑







```
# 查看续期定时器状态
sudo systemctl status certbot.timer

# 手动触发续期（仅对到期 <30 天的证书生效）
sudo certbot renew

# 模拟续期测试（不会真正续期，验证流程是否正常）
sudo certbot renew --dry-run

# 查看所有证书及到期时间
sudo certbot certificates
```

#### **续期后自动重载 Nginx**

bash

编辑







```
# 方式一：命令行参数
certbot renew --deploy-hook "systemctl reload nginx"

# 方式二：创建 hook 脚本（推荐，尤其适合 Docker 环境）
# /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh
#!/bin/bash
systemctl reload nginx   # 或 docker exec nginx nginx -s reload
chmod +x /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh
```

### **5. 撤销与删除证书**

bash

编辑







```
# 撤销证书（通知 CA 吊销，不可逆）
sudo certbot revoke --cert-path /etc/letsencrypt/live/example.com/cert.pem

# 删除证书及配置文件
sudo certbot delete --cert-name example.com

# 清理无效的符号链接
sudo certbot update_symlinks
```

### **6. 常见排错速查**

表格

| 错误信息                          | 原因与解决                                                   |
| :-------------------------------- | :----------------------------------------------------------- |
| `Could not bind to IPv4 or IPv6`  | 80 端口被占用，停掉其他服务或用 `webroot` 模式               |
| `Unauthorized / Invalid response` | DNS 未解析、防火墙拦截、webroot 路径错误                     |
| `Too many requests`               | 触发速率限制（同域名每周 5 张），等待或用 `--staging` 测试   |
| `nginx -t failed`                 | 现有 Nginx 配置有语法错误，先修复再申请                      |
| 续期成功但 HTTPS 仍过期           | 未配置 `--deploy-hook` 重载 Nginx，或容器环境证书未同步到挂载目录 |

#### **调试技巧**

bash

编辑

```
# 查看详细日志
certbot -v --debug

# 使用测试环境（不限速，签发无效证书，用于调试）
certbot certonly --staging --webroot -w /var/www/html -d example.com
```

------

### **📌 最佳实践清单**

- ✅ 生产环境优先用 `webroot` 模式，避免 `--nginx` 插件的路径兼容问题
- ✅ 始终配置 `--deploy-hook` 确保续期后服务自动重载
- ✅ 首次配置用 `--staging` 测试，确认无误再去掉该参数正式申请
- ✅ 定期检查 `certbot renew --dry-run` 输出
- ✅ 容器化部署时，确保证书目录已正确挂载到容器内
