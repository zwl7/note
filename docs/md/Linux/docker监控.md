# Docker 环境监控体系说明文档

## 一、监控体系整体架构

本监控体系基于 Docker 生态构建，采用「指标监控 + 日志监控」双维度方案，实现容器资源、服务性能、运行日志的全链路可观测，核心组件分工明确、协同工作，整体架构如下：

```
容器/服务运行
  ├─ 容器资源 → cAdvisor（采集资源指标） → Prometheus（存储/查询指标） → Grafana（可视化展示）
  └─ 容器日志 → Loki Docker Driver（推送日志） → Loki（存储/查询日志） → Grafana（可视化展示）
```

## 二、核心组件功能说明

### 1. cAdvisor：容器资源指标来源

#### 核心定位

专门采集 Docker 容器的**底层资源使用数据**，是容器资源监控的唯一数据源，不关注服务内部业务逻辑，仅监控容器「黑盒」资源消耗。

#### 核心功能

- 实时采集容器 CPU 使用率、CPU 时间片、内存使用量 / 工作集、网络收发流量、磁盘 I/O 读写量等资源指标；
- 暴露 Prometheus 兼容的 `/metrics` 接口，供 Prometheus 主动拉取指标；
- 支持容器启停状态、重启次数等基础运行状态监控。

#### 工作模式

- 被动暴露：cAdvisor 仅将指标整理后暴露接口，不主动推送数据；
- 数据流向：容器资源 → cAdvisor（采集 / 暴露） → Prometheus（拉取 / 存储）。

### 2. Prometheus：指标的「数据库 + 搜索引擎」

#### 核心定位

时序数据库 + 指标查询引擎，统一存储所有 cAdvisor、各类服务 Exporter 采集的指标数据，提供高效的指标查询与告警能力。

#### 核心功能

- 定时拉取：按配置频率（默认 15s）主动拉取 cAdvisor 等组件的 `/metrics` 指标；
- 时序存储：以「指标名 + 标签 + 时间戳 + 值」格式存储指标，支持数据保留策略（如默认 7 天）；
- 指标查询：通过 PromQL 语言实现指标的过滤、聚合、趋势计算（如容器 CPU 使用率、内存占比）；
- 告警规则：支持自定义告警规则（如 CPU 持续超阈值），对接告警组件实现异常通知。

#### 工作模式

- 主动拉取（Pull）：Prometheus 作为服务端，主动向各指标源拉取数据，稳定性高、易管控；
- 数据流向：cAdvisor/Exporter → Prometheus（拉取 / 存储） → Grafana（查询 / 展示）。

### 3. Loki：日志的「数据库 + 搜索引擎」

#### 核心定位

轻量级日志聚合系统，专门存储容器运行日志，提供高效的日志查询与检索能力，是日志监控的核心存储层。

#### 核心功能

- 日志存储：仅索引日志标签（如服务名、容器名），日志本体压缩存储，资源占用远低于 ELK；
- 日志查询：通过 LogQL 语言实现日志过滤、关键词检索、聚合统计（如查询服务错误日志、访问日志）；
- 多租户支持：支持开启多租户认证，实现不同业务 / 服务的日志隔离，适配生产集群环境。

#### 日志采集方式：Loki Docker Driver 插件

本体系不使用 Promtail 采集日志，而是采用 **grafana/loki-docker-driver** 插件（Docker 原生日志驱动），实现日志直接推送：

- 插件作用：作为 Docker 底层日志驱动，替代默认的 `json-file` 驱动，容器日志直接通过 Docker 内核推送给 Loki；
- 核心优势：无需额外运行采集进程，轻量化、Docker 原生集成，适配 Docker Swarm 集群运维；
- 工作模式：主动推送（Push），容器日志 → Docker Loki Driver → Loki（存储）。

### 4. Grafana：最终给人看的「仪表盘」

#### 核心定位

统一可视化平台，整合 Prometheus（指标）与 Loki（日志）数据源，提供直观的监控面板、日志查询界面，是监控数据的最终展示入口。

#### 核心功能

- 多数据源整合：同时对接 Prometheus（查指标）、Loki（查日志），实现「指标 + 日志」联动排查；
- 可视化面板：通过折线图、柱状图、单值统计等组件，展示容器资源趋势、服务性能指标、日志统计数据；
- 日志查询：内置 LogQL 编辑器，直接在面板中检索、过滤日志，支持日志高亮、上下文查看；
- 告警展示：对接 Prometheus 告警规则，在面板中展示告警状态、异常指标，支持告警通知配置。

#### 数据流向

- 指标维度：Prometheus → Grafana（查询 / 画指标图）；
- 日志维度：Loki → Grafana（查询 / 展示日志）。

## 三、组件协同工作流程

1. **指标采集与存储**：cAdvisor 实时采集容器资源指标并暴露接口 → Prometheus 定时拉取指标并存储 → Grafana 从 Prometheus 查询指标并生成资源监控面板；
2. **日志采集与存储**：容器输出 stdout/stderr 日志 → Docker 调用 Loki Driver 插件 → 插件将日志推送给 Loki 存储 → Grafana 从 Loki 查询日志并展示；
3. **异常排查**：Grafana 面板发现指标异常（如 CPU 飙高）→ 联动查询对应时间段的 Loki 日志 → 定位问题根源（如服务报错、资源瓶颈）。

## 四、核心优势

1. **轻量化**：无冗余组件，Loki 替代 ELK 大幅降低资源占用，Loki Driver 替代 Promtail 减少进程开销；
2. **Docker 原生适配**：基于 Docker 生态设计，Loki Driver、cAdvisor 与 Docker 无缝集成，适配 Docker Swarm 集群；
3. **全链路可观测**：覆盖「容器资源 - 服务指标 - 运行日志」全维度，实现问题快速定位；
4. **易运维**：组件部署简单，支持批量配置（如 Ansible 安装 Loki 插件），面板可复用现成 Dashboard，降低运维成本。
